# 数据模型

## 本地存储

- `localStorage`：key `travelExpenseAssistantData_v1`，存结构数据 + 汇率
- `IndexedDB`：库 `travelExpenseAssistant`，对象仓库 `files`（keyPath `id`），存附件 Base64
- 同步设置：`localStorage` key `travelExpenseAssistantSync_v1`（enabled / serverUrl / lastPushedRev / dirty / localUpdatedAt）
- 开启同步后，服务器端数据文件：`data/sync-state.json`（`{ rev, updatedAt, data }`，`data` 即下方整包结构）

## Trip（出差）

```json
{
  "id": "t_xxx",
  "name": "日本客户拜访",
  "region": "海外",              // 国内 | 海外
  "startDate": "2026-09-01",
  "endDate": "2026-09-07",
  "locations": [
    { "city": "东京", "startDate": "2026-09-01", "endDate": "2026-09-03" },
    { "city": "大阪", "startDate": "2026-09-03", "endDate": "2026-09-05" }
  ],
  "status": "出差中",
  "createdAt": 1750000000000,
  "expenses": []
}
```

状态机：`出差中 → 整理资料中 → 已生成报销包 → 已提交报销 / 审核中 → 已完成收款 → 已归档`

## Attachment（附件）

```json
{
  "id": "a_xxx",
  "filename": "bill.png",        // 原始文件名
  "mime": "image/png",           // image/jpeg | image/png | image/heic | application/pdf
  "docType": "收据",              // 账单 | 发票 | 付款截图 | 收据 | 支付记录 | 酒店账单 | 行程单 | 其他
  "size": 102400,
  "createdAt": 1750000000000
}
```

附件二进制以 Base64 存 IndexedDB `files`，`id` 对应；元信息存于 Expense.attachments。

## 资料完整性规则

```js
requiredDocs(type, subType, country, amountCny)
```

| 费用类型 | 国内 | 海外 | 超 1000 元增加 |
| --- | --- | --- | --- |
| 客情宴请 | 账单、发票、付款截图 | 收据 | 海外：发票、支付记录 |
| 个人餐费 | 账单、发票 | 收据 | 发票、支付记录 |
| 住宿费用 | 酒店账单、发票 | 收据 | — |
| 交通费用·出租车 / 高铁 | 发票 | 发票 | — |
| 交通费用·滴滴 / 飞机 | 发票、行程单 | 发票、行程单 | — |
| 其他费用 | 无强制要求 | 无强制要求 | — |

说明：
- `amountCny` = 金额 × 汇率（默认汇率可在导出页修改），CNY 为 1
- 完整度 = 资料齐全的费用笔数 ÷ 总费用笔数

## 附件命名规则

`费用类型-日期-地点-项目-金额-资料类型.扩展名`

- 地点：海外 = 国家名称+城市（如 `日本东京`）；国内 = 城市（如 `上海`）
- 项目：客情宴请/个人餐费 = 餐厅名称；住宿 = 酒店名称；交通 = 起终点/出发-目的/车站；其他 = 项目说明
- 金额：`8500JPY`、`86CNY`
- 示例：`客情宴请-2026-09-02-日本东京-XX餐厅-8500JPY-付款截图.png`

## 导出格式

### ZIP 资料包

```
2026-09-日本客户拜访-报销资料包/
├── 报销明细.xlsx
├── 客情宴请/ 个人餐费/ 住宿费用/ 交通费用/ 其他费用/
```

文件夹前缀取出差开始日期 `YYYY-MM`；同名文件自动加 `(2)` 后缀。

### 报销明细.xlsx 列

| 序号 | 费用类型 | 日期 | 国家 | 城市 | 项目 | 金额 | 币种 | 人民币金额 | 资料状态 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

- 费用类型：交通费用显示为 `交通费用（飞机）` 等
- 人民币金额：金额 × 汇率（四舍五入 2 位）
- 资料状态：`完整` 或 `缺少：发票、行程单`

### JSON 备份

```json
{
  "version": 1,
  "exportedAt": "2026-08-29T...Z",
  "rates": { "JPY": 0.05, "USD": 7.2 },
  "trips": [ /* Trip，附件含 data 字段(Base64) */ ]
}
```

## 汇率默认值

CNY=1, JPY=0.05, USD=7.2, EUR=7.8, KRW=0.0053, HKD=0.92, TWD=0.23, SGD=5.4, THB=0.21, GBP=9.3, AUD=4.8（可在导出页修改）。

## 合理性校验

```js
validateTrip(trip)      // 结束日期 >= 开始日期；各城市结束日期 >= 开始日期
validateExpense(trip, expense)
  // 1) expense.date 必须在 [trip.startDate, trip.endDate] 内
  // 2) 若 trip.locations 非空且 expense.city 非空，城市必须在行程城市列表中
```

- 费用表单实时提示不符合项，保存时强制拦截
- 出差表单保存时校验周期与城市；调整已有出差的周期 / 城市时，若有费用超出新范围会先确认
- 未设置行程城市 / 日期的旧数据不强制校验

## 同步协议

- `GET /api/state/meta` → `{ rev, updatedAt }`（轻量轮询，默认每 8 秒）
- `GET /api/state` → `{ rev, updatedAt, data }`（全量拉取）
- `PUT /api/state` body `{ data, baseRev, force }`：
  - `baseRev` 等于服务器当前 `rev` → 接受，`rev + 1`
  - 否则返回 `409 { conflict, server }`
  - `force: true` → 无条件接受（本地更新的冲突解决）
- **合并式同步（最终方案）**：
  1. 每次同步先 `GET /api/state` 拉取服务器全量数据
  2. 用 `mergeTrips()` 把远端合并进本地：出差 / 费用 / 附件按 id 做并集合并，同一实体的空字段用另一端补全（非空优先）
  3. 合并结果带新时间戳 `PUT` 回服务器（`baseRev` = 当前 rev；若遇 409 并发，则先重新合并服务器最新数据再 `force` 推送）
  4. 附件以 `data`（Base64）字段内嵌传输，应用后写入 IndexedDB
- 已知取舍：合并式同步不传播“删除”操作，删除的出差可能被另一台设备同步回来
- 同步载荷 `data`：`{ version, trips, rates, updatedAt }`，附件以 `data`（Base64）字段内嵌，应用后写入 IndexedDB
